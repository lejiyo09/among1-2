# Among Us 웹 (among1-2)

친구들과 서로 다른 기기의 **브라우저**에서 접속해 함께 하는 Among Us 스타일 온라인 멀티플레이 게임.
원작 스켈드 맵, 역할(승무원/임포스터), 미션 16종, 킬, 신고, 회의·투표, 사보타주, 벤트, 문, 유령까지 들어 있다.

- 서버가 모든 판정을 한다 (서버 권위): 역할, 이동, 킬 거리·쿨다운, 미션 정답, 신고, 투표 집계, 승리 판정
- 클라이언트는 화면과 입력만 담당하고, 자기 역할 외의 비공개 정보는 받지 않는다
- 빌드 단계가 없어 크롬북 브라우저(GitHub Codespaces / 웹 편집기)에서 바로 고치고 Render 로 배포할 수 있다

> Among Us™ 와 원작 그래픽·사운드는 Innersloth LLC 의 저작물이다. 이 프로젝트는 **비상업 팬 제작물**이다. 자세한 출처: [CREDITS.md](CREDITS.md)

## 빠르게 시작하기

```bash
npm install
npm start                    # http://localhost:3000
MIN_PLAYERS=2 npm run dev    # 둘이서 시험할 때 (코드 바뀌면 자동 재시작)
npm test                     # 단위·통합 테스트 (44개)
```

크롬북: [docs/deploy.md](docs/deploy.md) 의 "Codespaces" 부분 참고. 브라우저 탭을 여러 개 열면 탭마다 다른 플레이어가 된다.

## 배포 (Render)

Render 대시보드 → **New → Blueprint** → 이 저장소 선택. `render.yaml` 대로 Web Service 하나가 만들어진다.
정적 파일과 WebSocket(`/ws`)을 같은 서버가 제공하므로 다른 설정은 필요 없다. 비밀 키도 없다.
자세한 내용, 환경 변수, 무료 플랜 제약(15분 절전, 재시작 시 방 초기화): [docs/deploy.md](docs/deploy.md)

### 미구현 / 제한 사항 (솔직하게)

- **실제 Render 배포 주소에서의 다기기 테스트는 아직 하지 않았다.** 개발 환경에서는 Render 에 접근할 수 없었다. 배포 후 [docs/deploy.md](docs/deploy.md) 의 "배포 확인"을 직접 해 봐야 한다.
- Render 무료 인스턴스는 CPU 가 개발 PC 보다 훨씬 약하므로, 위 부하 수치보다 수용량이 적다. 배포 후 `/healthz` 의 `tickMsAvg` 로 확인할 것.
- 서버 재시작(재배포, 절전) 시 진행 중인 방은 사라진다 (메모리 저장). 클라이언트는 안내 후 메뉴로 돌아간다.
- 원작 기능 중 없는 것: 보안실 CCTV, 관리실 지도(인원 표시), 생체 신호(Vitals), 모자·펫 꾸미기, 다른 맵(폴루스·에어십·펑글), 특수 역할(엔지니어 등), 숨바꼭질 모드.
- 스켈드의 전력 우회는 원작의 2단계 대신 1단계, 쓰레기 비우기는 식당 → 창고 경로만 있다.
- 미라 HQ: 오염 제거실 자동 문, 벤트 청소 미션, 반복 무늬 복도 바닥 재질, 원자로·벤트 애니메이션은 없다. 로켓 연료 주입구 위치는 원작 좌표가 없어 로켓 아래로 정했다. 미니게임 모양은 원작 조작 방식을 따랐지만 그림은 원작 그대로가 아니다.
- 퍼즐형이 아닌 미션(연료, 다운로드 등)은 서버가 최소 수행 시간과 위치만 검증한다. 조작된 클라이언트도 시간을 줄이거나 멀리서 완료할 수는 없지만, 버튼 누르기 자체를 자동화하는 것은 막을 수 없다.
- 맵 그림은 팬 제작 스켈드(Z3_NON)라 원작과 방 크기가 조금 다르다. 미션·벤트·문 위치는 원작 데이터를 보고 이 그림에 맞춰 배치했다.
- 학교 방화벽이 WebSocket 자체를 막으면 접속할 수 없다 (HTTP 대체 경로 없음).

## 구조

```
server/            게임 서버 (Node.js + ws)
  index.js         HTTP 정적 파일 + /ws WebSocket, 보안 검사, 하트비트
  RoomManager.js   방 코드, 재접속 토큰, 30Hz 틱 루프
  net/Connection.js 전송 빈도 제한, 요청 ID 중복 방지
  game/Room.js     방 상태 머신 (로비→역할 공개→게임→회의→투표→결과→종료)
  game/rules.js    역할 배정·투표 집계·승리 판정 (순수 함수)
  game/tasks.js    미션 배정, 문제 생성, 정답 검증
  game/sabotage.js 사보타주와 문
shared/            서버·클라이언트 공용 (같은 코드로 예측과 판정이 일치)
  constants.js     원작 기본 설정, 색, 단계
  protocol.js      메시지 스키마와 런타임 검증
  map.js           Tiled 맵 해석, 충돌·시야 판정
  movement.js      결정적 이동 시뮬레이션
  tasks.js         미션 정의
  maps/skeld.tmj   스켈드 맵 (Tiled JSON: 충돌 타일 + 미션/벤트/문/방 오브젝트)
client/            브라우저 (빌드 없는 ES 모듈 + Phaser 3)
  js/net/          WebSocket 클라이언트, 맵 로더
  js/store.js      예측·보정·보간
  js/game/         Phaser 장면, 시야, 색 칠하기
  js/ui/           메뉴, 로비, HUD, 회의, 지도, 연출, 채팅
  js/tasks/        미션 미니게임 16종
  js/sabotage/     사보타주 수리 창
  dev/tasks.html   미니게임 단독 테스트 페이지 (/dev/tasks.html?game=wires)
tools/             맵 생성(build-map), 스프라이트 묶기, 부하 테스트
test/              node:test 테스트, e2e/ 브라우저 테스트
docs/              조사 보고서, 프로토콜, 배포
```

## 맵 고치기

`tools/skeld-objects.mjs` 에서 미션·벤트·문·장애물 위치를 고친 뒤:

```bash
npm run build:map -- --debug   # shared/maps/skeld.tmj 와 tools/out/skeld-debug.png(확인용) 생성
npm test                       # 모든 미션·벤트에 걸어서 갈 수 있는지, 문이 통로를 막는지 자동 검사
```

`shared/maps/skeld.tmj` 는 Tiled 맵 에디터로도 열 수 있다.
